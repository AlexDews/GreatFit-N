# Composable: system.config.ts

Этот файл является централизованным хранилищем конфигурации для всей экосистемы `Lumina Nexus`. Он позволяет управлять глобальными настройками, поведением системы и параметрами безопасности из одного источника, что упрощает масштабирование проекта.

## Назначение
Хранение статических настроек и параметров, используемых различными `composables` для реализации базового функционала (детект устройств, блокировка скролла, валидация файлов).

## Структура конфигурации

### 1. `bodyLock`
Управляет поведением интерфейса при открытии модальных окон или мобильного меню.
*   `delay`: Задержка (в мс) перед выполнением блокировки (синхронизация с CSS-анимациями).
*   `paddingAttr`: Селектор элементов, у которых нужно корректировать `padding-right` при блокировке скролла (чтобы хедер не "прыгал").
*   `lockClass`: Имя CSS-класса, который вешается на `body`.

### 2. `deviceDetection`
Объект с регулярными выражениями для определения типа устройства на стороне клиента. Используется для адаптивной логики.

### 3. `features`
Глобальные переключатели функционала проекта.
*   `imaskEnabled`: Глобальный тумблер для активации библиотеки `IMask` в приложении.

### 4. `security`
Базовый уровень защиты данных:
*   `enableSanitization`: Включение/выключение очистки данных.
*   `sanitizationLevel`: Уровень строгости очистки.
*   `maxFileSize`: Максимально допустимый размер загружаемого файла (в байтах).
*   `xssPatterns`: Массив регулярных выражений для детекта потенциальных XSS-атак в текстовых полях.
*   `allowedFileTypes`: Белый список MIME-типов для валидации загружаемых файлов.

### 5. `imageSupport`
Технический блок для проверки поддержки современными браузерами форматов `WebP` и `AVIF`. Содержит Base64-строки для быстрого тестирования поддержки форматов.

## Пример использования
Поскольку это `export const`, его можно импортировать в любой `composable` или компонент.

```typescript
// Пример использования в другом composable (например, useBodyLock.ts)
import { systemConfig } from '~/composables/system.config';

export const useBodyLock = () => {
  const { delay, lockClass } = systemConfig.bodyLock;
  
  const lock = () => {
    document.body.classList.add(lockClass);
    // ... логика с использованием delay
  };

  return { lock };
};
```

Советы по интеграции
Импорт: Используйте алиас ~/composables/system.config, так как Nuxt автоматически разрешает пути для этой директории.

Реактивность: Если вам нужно, чтобы настройки features менялись динамически (например, через Pinia), оберните systemConfig в reactive при импорте.

Безопасность: Не меняйте xssPatterns без необходимости, так как это может ослабить защиту вашего приложения.

# Composable: useBodyLock.ts

Этот composable предоставляет механизм для безопасной блокировки вертикальной прокрутки страницы. Он особенно полезен при открытии модальных окон, мобильных меню или попапов, предотвращая «прыжки» контента и фиксируя текущую позицию скролла пользователя.

## Назначение
Реализует плавную фиксацию `body` с сохранением позиции скролла, предотвращая случайное прокручивание страницы при открытых перекрывающих элементах интерфейса.

## Как работает
*   **Фиксация:** При вызове метода `lock` текущее положение прокрутки (`window.scrollY`) сохраняется, а `body` переводится в состояние `fixed` с отрицательным смещением `top`.
*   **Сброс:** При вызове `unlock` стили сбрасываются, и страница программно возвращается к сохраненной координате `scrollY`.
*   **Защита:** Внедрена система статусов (`bodyLockStatus`), которая предотвращает повторные или конфликтующие вызовы методов в течение заданного времени (`delay`), что критично при быстрой смене состояний интерфейса.

## API
*   `isLocked`: Реактивная переменная (`Ref<boolean>`), отражающая текущее состояние блокировки.
*   `lock(delay?: number, force?: boolean)`: Активирует блокировку. По умолчанию использует `delay` из `systemConfig`.
*   `unlock(delay?: number, force?: boolean)`: Снимает блокировку и восстанавливает позицию скролла.
*   `toggleLock(delay?: number)`: Переключает состояние блокировки.

## Пример использования
Используйте в любом компоненте Vue, где необходимо управлять скроллом (например, в компоненте попапа):

```vue
<script setup lang="ts">
import { useBodyLock } from '~/composables/useBodyLock';

const { lock, unlock, isLocked } = useBodyLock();

const openModal = () => {
  lock(); // Блокирует скролл
};

const closeModal = () => {
  unlock(); // Разблокирует скролл
};
</script>

<template>
  <button @click="isLocked ? closeModal() : openModal()">
    {{ isLocked ? 'Закрыть' : 'Открыть' }}
  </button>
</template>
```
Советы по интеграции
CSS-классы: Убедитесь, что в ваших глобальных стилях (например, в assets/scss/utils/base.scss) прописан класс lock (или тот, который указан в systemConfig.bodyLock.lockClass), который должен блокировать overflow: hidden у html или body.

SSR: Код защищен проверкой import.meta.client, поэтому безопасен для использования в Nuxt (не вызовет ошибок при серверном рендеринге).

Padding: Метод использует systemConfig.bodyLock.paddingAttr. Если у вашего хедера есть data-lp атрибут, скрипт будет учитывать его при расчетах, предотвращая сдвиг шапки при появлении скроллбара.

# Composable: useBurger.ts

Этот composable является контроллером для мобильного (или десктопного) бургер-меню в системе `Lumina Nexus`. Он обеспечивает управление состоянием меню, блокировку скролла страницы при его открытии, а также автоматизацию UX-задач, таких как закрытие меню при переходе по ссылкам или нажатии клавиши Escape.

## Назначение
Централизованное управление жизненным циклом меню: открытие, закрытие, переключение, обработка событий клавиатуры и автоматическое закрытие при навигации по маршрутам Nuxt.

## Как работает
*   **Состояние:** Использует глобальную `ref(false)` для синхронизации состояния `isMenuOpen` между всеми компонентами, использующими этот хук.
*   **Блокировка:** Интегрирован с `useBodyLock` для фиксации страницы при открытом меню.
*   **События:** Автоматически добавляет/удаляет слушатели событий `keydown` (для клавиши Escape) и очищает их при уничтожении компонента (`onUnmounted`).
*   **Навигация:** Использует `watch` для слежения за изменением `route.path`, что гарантирует автоматическое закрытие меню при переходе пользователя на новую страницу.
*   **Делегирование кликов:** Метод `handleMenuClick` позволяет удобно обрабатывать клики внутри меню (закрытие при клике по любой ссылке или бэкдропу).

## API
*   `isMenuOpen`: Реактивная переменная, хранящая состояние меню.
*   `openMenu()`: Открывает меню, блокирует скролл и активирует слушатели событий.
*   `closeMenu()`: Закрывает меню, разблокирует скролл и очищает слушатели.
*   `toggleMenu()`: Переключает состояние между открытым и закрытым.
*   `handleMenuClick(e: MouseEvent)`: Утилита для обработки кликов внутри контейнера меню.

## Пример использования
Интегрируйте этот хук в ваш компонент `TheHeader.vue` или любой другой, где располагается кнопка-бургер.

```vue
<script setup lang="ts">
import { useBurger } from '~/composables/useBurger';

const { isMenuOpen, toggleMenu, handleMenuClick } = useBurger();
</script>

<template>
  <button @click="toggleMenu" :class="{ '_active': isMenuOpen }">
    Меню
  </button>

  <div v-if="isMenuOpen" class="menu-container" @click="handleMenuClick">
    <!-- Ссылки или контент меню -->
    <a href="/about">О нас</a>
  </div>
</template>
```
Советы по интеграции
Конфигурация: Хук полагается на burgerConfig.menuOpenClass, импортированный из ~/components/modules/burger/config. Убедитесь, что в этом файле определен правильный CSS-класс, который будет добавляться к documentElement (обычно это <html>).

Оверлей: Чтобы работало закрытие по клику вне меню, добавьте класс menu-backdrop или атрибут data-click-dismiss элементу фона (оверлею) внутри вашего компонента меню.

SSR: Хук содержит проверки import.meta.client, поэтому он полностью совместим с серверным рендерингом Nuxt.

# Composable: useFormAjax.ts

Этот composable предоставляет стандартизированный способ отправки данных форм на сервер через AJAX с использованием встроенного в Nuxt метода `$fetch`. Он автоматически обрабатывает сериализацию данных и жизненный цикл состояния отправки.

## Назначение
Унифицировать взаимодействие с API для всех форм проекта, обеспечивая при этом возможность обработки ответов через кастомные события (Custom Events) и реактивное отслеживание статуса запроса (`isSending`).

## Как работает
*   **Гибкость данных:** Метод `sendFormAjax` автоматически определяет тип данных (`FormData` или обычный объект `Record`) и приводит их к `FormData` для корректной передачи на сервер.
*   **Инкапсуляция запроса:** Использует мощный `$fetch` от Nuxt, который эффективно работает как на клиенте, так и на сервере.
*   **Событийная модель:** При успехе или ошибке отправки вызываются `CustomEvent` (`modux:formSent` и `formError`). Это позволяет другим модулям системы (например, попапам с сообщением об успехе) «слушать» завершение отправки формы без прямой связи компонентов.
*   **Безопасность:** Вызовы событий DOM защищены проверкой `import.meta.client`, что исключает ошибки при выполнении на стороне сервера.

## API
*   `isSending`: Реактивная переменная (`Ref<boolean>`), которую можно использовать для блокировки кнопки «Отправить» во время выполнения запроса.
*   `sendFormAjax(action: string, method: HttpMethod, rawData: FormData | Record<string, unknown>, errorPopupId?: string)`:
    *   `action`: URL эндпоинта.
    *   `method`: HTTP-метод (`GET`, `POST`, и т.д.).
    *   `rawData`: Данные формы.
    *   `errorPopupId`: (Опционально) ID попапа, который следует вызвать при ошибке.

## Пример использования

```vue
<script setup lang="ts">
import { useFormAjax } from '~/composables/useFormAjax';

const { sendFormAjax, isSending } = useFormAjax();

const submit = async () => {
  const formData = { name: 'User', email: 'mail@test.ru' };
  
  const response = await sendFormAjax('/api/contact', 'POST', formData);
  
  if (response.success) {
    alert('Успешно отправлено!');
  }
};
</script>

<template>
  <form @submit.prevent="submit">
    <!-- поля формы -->
    <button :disabled="isSending">
      {{ isSending ? 'Отправка...' : 'Отправить' }}
    </button>
  </form>
</template>
```
Советы по интеграции
Глобальные обработчики: Так как хук генерирует CustomEvent, вы можете настроить глобальные слушатели в app.vue или ThePopup.vue, чтобы автоматически открывать окна успеха или ошибки при получении соответствующих событий, не привязывая логику к конкретной форме.

Типизация: Если ваша API возвращает строгую структуру данных, вы можете расширить sendFormAjax дженериками для типизации result.

SSR: Помните, что CustomEvent не будет работать на сервере. Если вам нужно обрабатывать формы на этапе SSR (например, для SEO или первичной отрисовки ошибок), используйте возвращаемое значение success/error напрямую в методе submit.

# Composable: useFormValidation.ts

Этот composable является «мозгом» системы валидации форм в `Lumina Nexus`. Он обеспечивает комплексную проверку полей, защиту от XSS-атак, валидацию файлов и вспомогательные функции для UI (например, автовысота textarea).

## Назначение
Валидация пользовательского ввода «на лету» или перед отправкой, защита данных и обеспечение доступности (Accessibility) для пользователей с ограниченными возможностями.

## Как работает
*   **Безопасность:** Встроенная проверка `containsPotentialXSS` сверяет данные с паттернами из `systemConfig.security`, блокируя подозрительный ввод.
*   **Валидация:**
    *   **Финансы:** Реализованы алгоритм Луна для банковских карт и проверка истечения срока действия (`checkExpiry`).
    *   **Форматы:** Проверка MIME-типов файлов и их размера через `systemConfig`.
    *   **Даты:** Умная проверка дат с учетом `minDateOffset` (например, нельзя выбрать прошедшую дату).
*   **Реактивность:** Все ошибки хранятся в объекте `errors` (`ref`), который автоматически обновляется при вызове `validateField`.
*   **Доступность:** Метод `announceErrors` создает временный скрытый элемент, который считывается скринридерами, оповещая пользователя о том, что в форме есть ошибки.

## API
*   `errors`: Реактивный объект, содержащий текущие ошибки (ключ — имя поля, значение — текст ошибки).
*   `validateField(fieldName, value, type, isChecked)`: Проверяет конкретное поле в зависимости от его типа.
*   `validateFiles(fieldName, files, allowedTypesStr)`: Проверяет массив файлов на соответствие типам и размеру.
*   `clearErrors()`: Полная очистка списка ошибок.
*   `updateTextareaHeight(e, maxH)`: Утилита для динамической подстройки высоты `textarea`.
*   `announceErrors()`: Вызывает системное оповещение для скринридеров.

## Пример использования

```vue
<script setup lang="ts">
import { useFormValidation } from '~/composables/useFormValidation';

const { errors, validateField } = useFormValidation();

const formData = ref({ email: '' });

const onBlur = () => {
  validateField('email', formData.value.email, 'email');
};
</script>

<template>
  <input v-model="formData.email" @blur="onBlur" />
  <span v-if="errors.email" class="error">{{ errors.email }}</span>
</template>
```
Советы по интеграции
Конфигурация: Хук тесно связан с formConfig (сообщения об ошибках, паттерны) и systemConfig (безопасность). Убедитесь, что оба файла настроены корректно.

Textarea: Для использования updateTextareaHeight добавьте обработчик @input на ваш <textarea>:
<textarea @input="updateTextareaHeight($event, 200)"></textarea>.

Accessibility: Всегда вызывайте announceErrors() после неудачной попытки отправки формы, чтобы пользователи скринридеров сразу узнали о проблеме.

# Composable/Directive: useIMask.ts

Этот файл реализует пользовательскую директиву Vue (`v-imask`), которая автоматизирует наложение масок на поля ввода (инпуты) с помощью библиотеки `IMask`. Она централизованно управляет конфигурацией масок через `formConfig`.

## Назначение
Обеспечение стандартизированного ввода данных пользователем (телефоны, даты, данные карт) и предотвращение ошибок форматирования. Директива сама следит за жизненным циклом элемента, инициализируя и уничтожая инстанс маски.

## Как работает
*   **Директива:** Использует хуки `mounted`, `updated` и `unmounted`, чтобы гарантировать, что маска всегда актуальна и корректно удаляется при исчезновении элемента из DOM.
*   **Гибкость выбора:** Поддерживает пять типов масок: `phone`, `card`, `cardExpiry`, `cardCvc` и `date`.
*   **Безопасность:** Работает только на стороне клиента (`import.meta.client`) и учитывает глобальный тумблер `systemConfig.features.imaskEnabled`.
*   **Интеллектуальный поиск:** Директива корректно находит поле `input` или `textarea`, даже если она была установлена на родительский компонент-обертку.

## API
Использование директивы в шаблоне:
```html
<input v-imask="{ type: 'phone' }" type="text" placeholder="+7 (___) ___-__-__" />
<input v-imask="{ type: 'date' }" type="text" placeholder="ДД.ММ.ГГГГ" />
```
Детали реализации
Date: Реализована сложная логика парсинга и форматирования дат (DD.MM.YYYY) с использованием диапазонов (IMask.MaskedRange) для каждого блока, что предотвращает ввод некорректных чисел (например, 99-й день или 13-й месяц).

Пересоздание: При изменении значения директивы (например, если тип маски динамически меняется в v-imask="{ type: dynamicType }") директива автоматически уничтожает старую маску и применяет новую.

Советы по интеграции
Глобальная регистрация: Чтобы использовать v-imask как v-imask, зарегистрируйте директиву глобально в Nuxt через плагин или локально в компоненте.

Конфигурация: Все настройки (шаблоны, флаги lazy) берутся из ~/components/modules/forms/config. Если вам нужно изменить маску телефона, редактируйте этот конфиг, а не саму директиву.

SSR: Директива защищена проверками на import.meta.client, поэтому не вызовет проблем при рендеринге на стороне сервера.

# Composable: useScrollHeader.ts

Этот composable реализует логику «умного» хедера, который динамически реагирует на действия пользователя при прокрутке страницы. Он обеспечивает плавное появление хедера при скролле вверх и его скрытие при скролле вниз, а также фиксирует хедер при удалении от верха страницы.

## Назначение
Создание UX-эффекта адаптивного меню, которое не занимает лишнее экранное пространство при чтении контента, но всегда доступно при попытке пользователя вернуться к навигации.

## Как работает
*   **Игнорирование событий:** Хук интегрирован с `useBodyLock`. Если страница заблокирована (открыт попап/бургер), логика скролла замораживается, предотвращая «дерганье» хедера.
*   **Пороговые значения:** 
    *   При скролле `y <= 20` хедер сбрасывает состояния фиксации и показа.
    *   При `y > 20` хедер переходит в состояние `isFixed`.
*   **Направление прокрутки:** Сравнивая текущую позицию `y` с `lastScrollTop` (с учетом порога в 5px), хук определяет направление движения. При скролле вверх (`y < lastScrollTop`) хедер показывается (`isShow = true`), при скролле вниз — скрывается.
*   **События:** Поддерживает как нативный `window.scroll`, так и кастомное событие `smooth-scroll-move`, что позволяет корректно работать даже в системах с реализованным "плавным скроллом" (smooth scroll).

## API
*   `isFixed`: `Ref<boolean>` — хедер находится в фиксированном состоянии (отдалился от верха).
*   `isShow`: `Ref<boolean>` — хедер видимый (показывается пользователю).
*   `isAnimating`: `Ref<boolean>` — сигнализирует о том, что хедер готов или находится в процессе анимации (активируется после прохождения `startPoint`).

## Пример использования
Используйте в корневом компоненте хедера (например, `TheHeader.vue`):

```vue
<script setup lang="ts">
import { useScrollHeader } from '~/composables/useScrollHeader';

const { isFixed, isShow, isAnimating } = useScrollHeader();
</script>

<template>
  <header 
    :class="{ 
      '_fixed': isFixed, 
      '_show': isShow, 
      '_animating': isAnimating 
    }"
  >
    <!-- Контент хедера -->
  </header>
</template>
```
Советы по интеграции
Конфигурация: Порог старта анимации берется из scrollConfig.header.startPoint. Убедитесь, что этот параметр задан в ~/components/modules/scroll/config, иначе хедер может вести себя непредсказуемо.

CSS: Логика хука управляет только классами/состояниями. Вам необходимо прописать CSS-переходы (transitions) для класса _show или _fixed для достижения плавного эффекта.

Производительность: Обработчик нативного скролла привязан с опцией { passive: true }, что обеспечивает высокую производительность и не блокирует основной поток прокрутки браузера.

# Composable: useSmoothScroll.ts

Этот composable реализует плавную прокрутку (smooth scroll) к нужному блоку страницы с учетом высоты хедера. Он обеспечивает контролируемую анимацию, которая учитывает состояние интерфейса (открытое меню) и синхронизируется с другими системными компонентами.

## Назначение
Создание плавного UX при навигации по якорям (например, по пунктам меню), обеспечивая корректное позиционирование с учетом фиксированных элементов (шапки сайта).

## Как работает
*   **Конфигурация:** Использует настройки из `scrollConfig.goto` (скорость, отступы).
*   **Интеграция с UI:** Автоматически закрывает бургер-меню, если оно открыто (используя селекторы из `scrollConfig`), что улучшает UX мобильной навигации.
*   **Расчет позиции:** Вычисляет точную координату, учитывая высоту хедера (`offsetHeight`) и пользовательские отступы (`offsetTop`), что гарантирует, что контент не окажется под фиксированным хедером.
*   **Математика анимации:** Использует `requestAnimationFrame` и функцию *Quadratic Ease-in-out* для создания плавной и естественной анимации движения.
*   **Синхронизация:** В процессе «полета» постоянно вызывает кастомное событие `smooth-scroll-move`. Это критически важно для работы `useScrollHeader`, чтобы хедер мог корректно скрываться/показываться прямо во время прокрутки.

## API
*   `goToBlock(targetBlockSelector: string, options?: object)`:
    *   `targetBlockSelector`: CSS-селектор элемента, к которому нужно прокрутить страницу.
    *   `options`: Объект для переопределения параметров (например, `{ speed: 1000 }` или `{ noHeader: true }`).

## Пример использования

```vue
<script setup lang="ts">
import { useSmoothScroll } from '~/composables/useSmoothScroll';

const { goToBlock } = useSmoothScroll();
</script>

<template>
  <button @click="goToBlock('#contacts')">
    Перейти к контактам
  </button>
  
  <section id="contacts">
    <!-- Контент -->
  </section>
</template>
```
Советы по интеграции
Конфигурация: Убедитесь, что в ~/components/modules/scroll/config заданы правильные значения для header (селектор шапки), burgerBtn и menuOpenClass.

SSR: Хук защищен проверкой import.meta.client, поэтому безопасен для использования в Nuxt-приложениях.

События: Если у вас есть другие модули, которые должны реагировать на изменение позиции скролла во время анимации, слушайте событие window.addEventListener('smooth-scroll-move', ...) — оно передает текущую координату y в event.detail.y.

# Composable: useSystemInit.ts

Этот composable выполняет роль «загрузчика» (bootloader) системы `Lumina Nexus`. Он инициализирует базовые параметры среды исполнения, определяет возможности браузера и применяет необходимые CSS-классы к тегу `<html>` для корректной работы верстки.

## Назначение
Автоматическая настройка окружения при старте приложения: определение поддержки форматов изображений, адаптация под мобильные устройства и фиксация размеров экрана для корректной работы `100vh`.

## Как работает
*   **Детекция устройств:** Использует регулярные выражения из `systemConfig.deviceDetection` для идентификации мобильных платформ.
*   **Поддержка форматов:** Проверяет поддержку `WebP` и `AVIF` путем загрузки Base64-строк из конфига, добавляя соответствующие классы к `documentElement` (например, `avif`, `webp` или `no-webp-avif`).
*   **Фикс 100vh:** Решает известную проблему мобильных браузеров, где `100vh` включает высоту адресной строки. Устанавливает CSS-переменную `--vh`, основанную на `window.innerHeight`, для элементов с атрибутом `[data-fullscreen]`.
*   **Состояния:** Автоматически добавляет класс `loaded` после полной загрузки страницы (`window.onload`) и класс `touch` для мобильных устройств.

## API
*   `useSystemInit()`: Функция-инициализатор, которую следует вызвать один раз в `app.vue` или корневом плагине для запуска всех системных процессов.

## Пример использования
Вызывайте этот хук при старте приложения в `app.vue`:

```vue
<script setup lang="ts">
import { useSystemInit } from '~/composables/useSystemInit';

// Запускаем инициализацию ядра системы
useSystemInit();
</script>
```
CSS-переменная: В CSS используйте --vh для задания высоты полноэкранным секциям, чтобы избежать «прыжков» интерфейса:

CSS
[data-fullscreen] {
  height: 100vh; /* Фоллбек для десктопа */
  height: calc(var(--vh, 1vh) * 100); /* Фикс для мобильных */
}
Производительность: Хук запускается внутри onMounted, что гарантирует выполнение логики только после того, как Nuxt отрендерит DOM-дерево на клиенте.

Конфигурация: Все настройки детектирования устройств и Base64-заглушки для изображений хранятся в ~/composables/system.config.ts.
